Why this matters to a client

A reservations assistant needs a clean list of records to follow up without losing or guessing at customer information. I built a repeatable check that keeps the source intact, attaches a reason to each flagged row, and accounts for every booking. The 115 flagged rows are 0.32% of this file; that is a review rate for two rules, not an improvement percentage.

02 / PROCESS

Source to review queue.

The script reads the CSV one row at a time. It writes aggregate counts by default and can create a private local queue of flagged rows for human follow-up.

  1. 01Read source

    Check required columns and stream each booking row.

  2. 02Apply rules

    Validate the calendar date and total nights.

  3. 03Queue exceptions

    Count each reason and any overlap.

  4. 04Reconcile

    Confirm passed plus review equals all rows.

RULE 01

Invalid arrival date

Build a real calendar date from year, month, and day. A date such as February 29, 2018 fails because 2018 was not a leap year.

37rows flagged
RULE 02

Zero-night stay

Add weekend and weekday nights. A reservation with zero of both enters review because it has no booked stay length.

78rows flagged

No rows triggered both findings in this dataset. The script also guards against missing, non-numeric, or negative night counts; none appeared in this source.

Operating procedure

  1. Check the input

    Confirm the required date and night columns before running the local Python script.

  2. Filter and reconcile

    Review the aggregate JSON; rows that pass these rules plus rows for review must equal source rows.

  3. Follow up privately

    If row-level follow-up is needed, create the optional local review CSV outside the site. Check each flagged booking against its source before changing or removing a record.

  4. Record the decision and rerun

    For a real processing task, document each approved correction, rerun the checks, and preserve the before-and-after counts.
