EARLIER TECHNICAL STUDY / ML ANALYSIS

Transaction review (ML study)

An earlier credit card transaction study using data preparation and One-Class SVM to prioritize unusual records for human review.

ROLE
Machine learning research
FORMAT
Model evaluation
TOOLS
Python, scikit-learn, One-Class SVM, Grid Search
STATUS
Earlier research project; no customer records shown

The problem

Rare or unusual transactions are difficult to review one by one. A model can help prioritize cases, but a sensitive anomaly detector may change substantially when features or model parameters change.

What I worked on

  • Prepared transaction features for model input and selected the features used for analysis.
  • Scaled the features before fitting a One-Class SVM.
  • Used Grid Search to compare parameter settings and presented the evaluation with statistical summaries and visualizations.

Review procedure

  1. Record the dataset version, permitted fields, and quality checks before modeling.
  2. Keep evaluation data separate while fitting preprocessing and candidate models.
  3. Compare parameter settings on the evaluation data and inspect both missed anomalies and false alerts.
  4. Document the chosen settings and rerun the same checks when the data changes.

This is a practical repeat-run checklist; the original portfolio does not document every evaluation detail needed to audit the earlier model result.

Relevant data skill

The study demonstrates careful preparation of source data and a review-first approach to unusual records. A flagged transaction is a lead for investigation, not a final fraud decision.

Evidence and limits: The project is described in my earlier portfolio. The dataset split, class balance, confusion matrix, and operating threshold are not documented here, so this page does not present a performance percentage as a validated result.
