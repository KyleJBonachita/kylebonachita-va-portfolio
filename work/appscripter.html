BUILT PROJECT / AUTOMATION + WEB

Appscripter

A local dashboard and CLI that turns Google Apps Script source into a reviewed Git backup, with separate paths for private preservation and a shareable copy.

ROLE
Tool design, frontend, workflow and safeguards
FORMAT
Local web dashboard + CLI
TOOLS
Node.js, clasp, Git, HTML, CSS, JavaScript
STATUS
Built local project

Why I built it

Apps Script can contain important automation logic, but a manual source export is easy to postpone or handle inconsistently. Sharing it also needs care: source files can include identifiers and references that should be reviewed before anything is published. I built one repeatable path for preserving source privately and preparing a separate copy for review.

What I built

  • A dashboard and command-line flow for downloading Apps Script source through clasp.
  • One path for exact private backups and another for best-effort redacted, shareable copies.
  • Static checks and synthetic fixtures to review the source without opening linked business data.
  • A human review step before optional GitHub repository creation or push.

Why it works this way

Limit access. The export targets script source files and does not follow links to spreadsheets or Drive data.

Keep the choices visible. Private backups and shareable copies have different rules, so the tool makes the mode explicit.

Review before publishing. The user inspects the result before any optional GitHub action.

Operating procedure

  1. Select a script and backup mode

    Choose an exact private backup or a separate best-effort shareable copy before exporting.

  2. Export source with clasp

    Download the Apps Script project files without following links to connected Sheets or Drive content.

  3. Run checks and inspect the files

    Review static warnings and any redaction output. Treat a clean check as a prompt for human inspection, not proof that the files are safe to publish.

  4. Store or publish deliberately

    Keep exact backups private. Create or push a shareable Git repository only after inspecting the final copy.

Outcome and limits

The built dashboard and CLI provide both backup paths and a review step. The case study demonstrates the workflow and safeguards; it has no measured before-and-after time study or client deployment claim. Redaction is best effort, so a person still decides whether a copy can be shared.
